# Плагины toonop

Исходники плагинов редактора [toonop](https://github.com/GeTechG/toonop).
В `master` — исходники, в ветке `build` — собранные бандлы и каталог, который
читает редактор:

```
https://raw.githubusercontent.com/GeTechG/toonop_plugins/build/index.json
```

Этот адрес уже стоит в редакторе по умолчанию: **Настройки → Плагины**, вкладка
«Каталог».

## Что такое плагин

Один ES-модуль, отдающий `export default` с манифестом: `id`, `api` — мажор
контракта — и то, что плагин приносит редактору.

Контракт — это [`types/toonop.ts`](types/toonop.ts): что можно принести, в
какой форме и какие числа формата при этом в ходу. Обычный модуль, он
собирается в ваш бандл вместе с остальным. Мажор пишите числом — тем, под
который писали; какой он сейчас, сказано там же. Это ваше слово о
совместимости, и подставлять его за вас никто не должен. Манифест, не
приносящий ничего, не грузится.

Плагин самодостаточен: всё, что ему нужно, приезжает в его собственном бандле.
Из редактора он получает ровно один объект — `host`, и ничего больше.

Толщина и любые пороги, которыми кисть прореживает точки, — логические
пиксели, и ничем по размеру документа они не делятся: пиксель есть пиксель,
кисть на 9 кладёт линию в девять пикселей в документе любого размера.
Повторяете редактор, рисовавший на холсте другого размера, — приведите его
числа один раз, когда объявляете: умножьте на `1280 / <его холст>`.

Плагин **не придумывает свой вид примитива**: он кладёт в кадр то, что формат
уже знает и рендерер уже рисует. Иначе получился бы кадр, который нельзя
показать никому, кроме редактора с этим плагином — ни плееру, ни экспорту, ни
опубликованному мультику.

## Как завести свой

```
plugins/<id>/
  package.json     name = <id>, version = 1.2.3, description, toonop.title, toonop.icon
  icon.svg         24×24, одна линия чернил (viewBox="0 0 24 24")
  src/index.ts     export default манифест
```

`package.json` обязан иметь скрипт `build`, который кладёт `dist/plugin.js` —
один самодостаточный ESM-файл. Чем собирать, дело ваше; в примере
[`plugins/straight-line`](plugins/straight-line) это esbuild:

```json
"build": "esbuild src/index.ts --bundle --format=esm --target=es2022 --outfile=dist/plugin.js"
```

Собрать всё и получить каталог в `dist/`:

```sh
npm install
npm run build
```

### Проверить в редакторе

Два пути, оба без пересборки редактора:

- **Файлом.** Настройки → Плагины → «Мои» → «Установить файлом…» и выбрать
  `plugins/<id>/dist/plugin.js`. Поставленный так плагин помечается локальным и
  каталогом не обновляется.
- **Своим каталогом.** Поднять `dist/` любым статическим сервером
  (`npx serve dist`) и вписать его адрес в Настройки → Плагины → «Адрес
  каталога».

## Как прислать

1. Форк, ветка, плагин в `plugins/<id>/`.
2. PR в `master`. Экшен соберёт все плагины; если ваш не собирается, проверка
   красная.
3. После merge экшен сам выложит бандлы и `index.json` в ветку `build` — в
   редакторах плагин появится в каталоге, а у тех, у кого он уже стоит,
   обновится при следующем запуске.

Версию поднимайте в `package.json`: именно по ней редактор понимает, что вышло
новое. Версия — `major.minor.patch`.

## Что смотрят на ревью

- Плагин делает то, что написано в описании, и ничего сверх того.
- Никаких запросов наружу и никакой работы с чужими данными: плагин исполняется
  в контексте редактора со всеми правами страницы, песочницы нет. Ревью — это и
  есть защита.
- CSS-правила плагина несут префиксом его `id`; опираться можно только на
  публичные классы редактора (`.key`, `.toggle`, `.sheet-*`, `.saved`).
- Бандл самодостаточен: ни одного импорта наружу.

## Если плагин сломался

Редактор ловит исключение на границе плагина: плагин отключается сам, в списке
«Мои» появляется отметка об ошибке, подробности — в консоли браузера. Редактор
при этом продолжает работать. Заводите issue с тем, что в консоли.

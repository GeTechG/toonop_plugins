# Плагины для редактора toonop

В `master` — исходники, в ветке `build` — собранные бандлы и каталог, который
читает редактор:

```
https://raw.githubusercontent.com/GeTechG/toonop_plugins/build/index.json
```

Этот адрес стоит в редакторе по умолчанию: **Настройки → Плагины → «Каталог»**.

## Что такое плагин

Один ES-модуль, отдающий `export default` с манифестом: `id`, `api` — мажор
контракта, числом — и то, что плагин приносит редактору. Контракт лежит в
[`types/toonop.ts`](types/toonop.ts) и собирается в ваш бандл как обычный
импорт.

- Бандл самодостаточен: ни одного импорта наружу, из редактора приходит ровно
  один объект — `host`.
- Свой вид примитива придумывать нельзя: в кадр кладётся то, что уже знает
  формат и рисует рендерер. Иначе кадр не покажет ни плеер, ни экспорт, ни
  опубликованный мультик.

## Как завести свой

```
plugins/<id>/
  package.json     name = <id>, version = 1.2.3, description, toonop.title, toonop.icon
  icon.svg         24×24, одна линия чернил (viewBox="0 0 24 24")
  src/index.ts     export default манифест
```

`package.json` обязан иметь скрипт `build`, кладущий `dist/plugin.js` — один
самодостаточный ESM-файл. Чем собирать, дело ваше; в примере
[`plugins/straight-line`](plugins/straight-line) это esbuild:

```json
"build": "esbuild src/index.ts --bundle --format=esm --target=es2022 --outfile=dist/plugin.js"
```

Собрать всё и получить каталог в `dist/`:

```sh
npm install
npm run build
```

### Проверить в редакторе

Оба пути — без пересборки редактора:

- **Файлом.** Настройки → Плагины → «Мои» → «Установить файлом…»,
  `plugins/<id>/dist/plugin.js`. Такой плагин помечается локальным и каталогом
  не обновляется.
- **Своим каталогом.** Поднять `dist/` статикой (`npx serve dist`) и вписать
  адрес в Настройки → Плагины → «Адрес каталога».

## Как прислать

1. Форк, ветка, плагин в `plugins/<id>/`.
2. PR в `master`. Экшен собирает то, что изменилось; плагин, который не
   собирается или просит не тот мажор контракта, валит проверку.
3. После merge экшен выкладывает бандлы и `index.json` в ветку `build`: плагин
   появляется в каталоге, а установленный обновляется при следующем запуске.

Версию поднимайте в `package.json` — по ней редактор понимает, что вышло новое.
Формат `major.minor.patch`.

## Если плагин сломался

Редактор ловит исключение на границе плагина: плагин отключается, в «Моих»
появляется отметка об ошибке, подробности — в консоли. Заводите issue с тем,
что в консоли.
